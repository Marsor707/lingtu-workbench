# Windows 启动问题自查（给反馈用户的操作清单）

适用现象：双击 `灵图工作台.exe` 后，托盘提示「正在启动本地服务」，浏览器一直没有打开页面，重启电脑也没有改善。

> 目标：30 秒内拿到「本地服务到底报了什么错」。1.0.10 起托盘右键菜单里有「状态」「打开日志目录」「打开数据目录」三项，可以直接跳过前两步。

## 第 1 步：看托盘菜单的真实状态（1.0.10 起）

右键托盘图标，看第一项「状态」：

| 显示 | 含义 | 下一步 |
| --- | --- | --- |
| `状态：正在启动本地服务` | 服务进程已拉起，还没回报就绪 | 等 30 秒；仍在启动中→第 1.1 步 |
| `状态：本地服务未就绪 · 本地服务进程意外退出（退出码 N）` | 服务进程崩了 | 第 2 步 |
| `状态：本地服务未就绪 · 20 秒内没有输出就绪信息` | 进程活着但卡住 | 第 2 步 |
| `状态：本地服务未就绪 · 端口 8765 未被释放` | 端口被别的进程占着 | 第 3 步 |
| `状态：检测到旧版本服务在运行（vX.Y.Z）` | 有旧版残留进程 | 点「重启本地服务」 |

菜单里同时有「打开日志目录」，点开以后把 `launcher.log` 发给我们即可。

### 1.1 手工启动本地服务（最关键的一步）

1. 右键托盘图标 →「退出」，确保后台没有残留进程。
2. 在安装目录（默认 `%LOCALAPPDATA%\灵图工作台`，或用户自选的文件夹）空白处 `Shift + 右键` →「在此处打开 PowerShell 窗口」。
3. 执行：

```powershell
.\lingtu-server.exe
```

4. 把窗口里的输出**整段截图或复制**给我们。正常情况会打印一行 `{"ready":true,"port":8765,...}`；失败时会直接打印 Node 的报错（例如数据库打不开、端口被占、文件被安全软件拦截）。

## 第 2 步：确认安全软件没有拦掉服务程序

管理员 PowerShell 执行：

```powershell
Get-MpThreatDetection | Select-Object -Last 5
```

如果看到 `lingtu-server.exe` 被隔离或删除的记录，请在 Windows 安全的「病毒和威胁防护 → 保护历史记录」里恢复并加入排除项，然后重装一次。

## 第 3 步：确认 8765 端口被谁占用

```powershell
netstat -ano | findstr :8765
```

拿到最后一列的 PID 后：

```powershell
Get-Process -Id <PID> | Select-Object Id,ProcessName,Path
```

如果占用者不是 `lingtu-server`，把进程名和路径发给我们——本地服务会回退到随机端口，托盘状态会显示真实端口。

## 第 4 步：回传这些文件

1. 托盘右键 →「打开日志目录」→ `launcher.log`
2. 托盘右键 →「打开数据目录」→ `workspace\logs\execution.log`
3. 第 1.1 步手工启动的控制台输出
4. 系统版本（`winver` 截图）

有了这四样，基本可以定位到具体环节；缺少日志时只能靠猜。

## 升级前备份提示词（网页打不开也能做）

提示词库、API Key、任务历史都在一个磁盘文件里，**不需要打开网页**就能备份。

1. **先彻底退出应用**：托盘图标右键 →「退出」。托盘没有或退出无效时，按 `Ctrl + Shift + Esc` 打开任务管理器，结束 `灵图工作台`（`lingtu-workbench.exe`）和 `lingtu-server.exe`。
   这一步不能省：数据库用 WAL 模式，运行中还有 `-wal` 文件在写，运行中复制可能拿到半份数据。
2. 按 `Win + R`，粘贴下面这行后回车：
   ```
   %APPDATA%\com.lingtu.workbench
   ```
3. 把打开的文件夹**整个**复制到桌面或 U 盘，改个名字，例如 `lingtu-backup-20261021`。
   - 里面通常是 `lingtu.db`、`lingtu.db-wal`、`lingtu.db-shm` 三个文件，**必须一起复制**；只拷 `lingtu.db` 可能丢掉最近录入的提示词。
   - 如果这个路径打不开，说明数据还没搬过位置（更早的版本或从没存过提示词），把第 1.1 步的结果发给我们即可。
4. 历史图片另存一份：安装目录下的 `workspace` 文件夹（默认 `%LOCALAPPDATA%\灵图工作台\workspace`，或当初自选的那个安装文件夹）。

**隐私提醒**：`lingtu.db` 里的 API Key 是明文保存的。备份文件只自己留存，不要发到群里，也不要作为报障材料发出来——报障只需要 `launcher.log` 和 `execution.log`。

### 什么时候需要手动恢复

只要原来那个文件夹还在原位（上面第 3 步是「复制」，不是「移动」），装好 1.0.10 后**首次启动会自动迁移**，不需要手动做什么。

只有在自动迁移没发生时（例如升级过程中把原文件夹删了）才手动恢复：

1. 退出应用。
2. 新建目录 `%LOCALAPPDATA%\lingtu-workbench-data`。
3. 把备份里的 `lingtu.db`、`lingtu.db-wal`、`lingtu.db-shm` 复制进去。
4. 启动应用，托盘右键「状态」应变成「运行中」，再打开页面确认提示词回来了。

## 退出码 134 的含义（1.0.11 起可直接看托盘）

`134` 是 Node 的 `SIGABRT`，日志里会跟着一行 `FATAL ERROR: ...`：

- `Reached heap limit Allocation failed - JavaScript heap out of memory`：历史库太大，启动时把整张任务表读进内存爆掉了。1.0.11 已修（列表不再携带源图 base64）。
- 其他 `FATAL ERROR`：把 `launcher.log` 里那几行发我们。

## 数据目录在哪、怎么换

- 默认：`%LOCALAPPDATA%\lingtu-workbench-data`（数据库 + `workspace\jobs` 里的图片）。
- 托盘右键 →「打开数据目录」直接定位；「更换数据目录…」可以把整个数据目录搬到别的盘（如 `E:\灵图数据`），复制完自动重启服务，旧目录保留不删。
- 选择结果记在 `%LOCALAPPDATA%\lingtu-workbench-data-root.txt`。若它指向的目录不存在（移动硬盘没插、目录被删），托盘会显示「上次选择的数据目录不存在：…」，用「更换数据目录…」重选即可，数据不会被自动替换成别的目录。
- 建议只选本地固定盘；网络盘上 SQLite 的锁语义不可靠。

## 数据库越来越大怎么办

1.0.13 起任务队列提供「清理已完成」：只删除已完成的任务记录，**不会删掉已生成的图片文件**（图片仍在工作区里，占用磁盘），清理后会自动在后台压缩数据库，提示条会显示回收了多少空间。

- 只能整体清理已完成任务，或保留最近 7 / 30 / 90 天；
- 运行中、排队、待复核、失败、已取消的任务不会被清理；
- 清理期间页面可正常使用；压缩在后台进行，GB 级库可能持续几十秒到几分钟。
