# ADR 0015：本地服务端口回退与托盘状态文案

## 状态

已采用

## 背景

Windows 用户反馈「托盘图标在，浏览器打开 `127.0.0.1:8765` 却拒绝连接」，排查时又按开发文档试了 `5173`。事后看，代码本身把这个故障做成了不可诊断、也不可自救：

1. 端口是硬编码的：启动器注入 `LINGTU_PORT=8765`，前端 `src/api-base.ts` 也写死 `127.0.0.1:8765`。8765 一旦被别的东西占用，sidecar `listen` 报 EADDRINUSE 后直接退出，整个产品不可用。
2. 失败是静默的：启动器建托盘与 sidecar 是否就绪无关，探活失败只写日志、不改托盘状态；sidecar 的 stdout/stderr 只 `emit` 给一个不存在的 webview，release 构建也不写日志文件。用户看到的「图标在」被合理误读为「服务在」。
3. `5173` 是 Vite 开发端口，正式安装包永远不会监听它，出现在用户可见的材料里只会制造第二个假故障。

于是用户唯一的动作就是来找开发者，而开发者没有任何线索。

## 决策

- **端口回退**：sidecar 默认仍用 8765；`listen` 遇到 EADDRINUSE 时以系统分配端口重试一次（`server/index.ts` 的 `startServer`）。显式指定的 `LINGTU_PORT` 被占用时同样回退，规则只有一条，少一个分支。启动器不再注入 `LINGTU_PORT`。
- **ready JSON 是就绪与端口的唯一事实来源**：sidecar 启动成功后输出的 `{"ready":true,"port":N}` 由启动器解析，用它去做探活与打开浏览器。TCP 探测只保留两处用途：启动前识别 8765 上是不是自己人、就绪后刷新执行中任务数。
- **`/health` 增加 `version` / `pid` / `runningJobs`**：前两者用于识别「同版本实例」与「旧版本实例」，后者是托盘禁用重启的唯一依据。
- **前端改用同源相对路径**：页面本来就由本地服务托管，请求走相对路径；开发模式改由 `vite.config.ts` 的代理转发到 `127.0.0.1:8765`。端口回退因此对页面透明。
- **托盘状态与文案**：状态机为「启动中 / 就绪 / 未就绪 / 重启中 / 检测到旧版本服务在运行」，有执行中任务时叠加「有 N 个任务执行中」。tooltip 与两个菜单项（打开、重启）的文案与可用性都由状态推导，抽成纯函数并由 `cargo test` 锁定。
- **未就绪时主项即「重启并打开」**：用户点这个菜单项的意图永远是「我要用」，不把他引向一个拒绝连接的页面。
- **重启总是打开新标签页**：端口可能变化，旧标签页会指向失效端口。
- **有执行中任务时禁用重启**：服务启动只重排 `queued` 任务，被中断的 `running` 任务不会恢复也不会标失败，重启会让它永久停在执行中。
- **接管旧版本实例要复核身份**：`/health` 上的 `pid + version` 与探测时一致才按 pid 强杀（Windows `taskkill /PID /F`），随后必须确认端口已释放，否则不启动新实例——宁可停在「检测到旧版本服务在运行」，也不能让两个服务写同一个数据库、重复执行同一批任务。
- **不做**：sidecar 意外退出后的自动重启（会与「重启会打断任务」叠加成静默事故）、系统通知插件、单实例插件与互斥体、任务中断恢复、页面侧失效提示。

## 结果

- 端口冲突从「产品整体不可用」变成「用户无感」；托盘第一次成为可信的状态面，用户能自己判断并一键恢复到可用状态。
- 与 ADR 0013 的关系：sidecar 的父进程自杀机制不变，端口回退不改变生命周期通道；但「旧版本实例还活着」从此有了明确的、由用户触发的接管路径，而不是静默双跑。
- 代价：重启后旧标签页会静默失效，只能从托盘重新打开；开发模式下若 8765 被占，Vite 代理的固定 target 会指向占位进程，需要手工改 target。
- 代价：如果 8765 被一个**非本项目**的程序占用，本地服务会退到别的端口，而用户手输 `127.0.0.1:8765` 打开的是那个程序——托盘路径不受影响，但「手输固定地址」这个旧习惯不再可靠。
- 未覆盖的相邻缺陷：release 版仍然不写日志文件，sidecar 的 stderr 依旧没有落盘去处；这次只解决了用户能自救，没有解决事后取证。
- 未覆盖的相邻缺陷：识别「已有同版本实例」只探测 8765。如果 8765 被非本项目程序占用、而本地服务已经回退到别的端口，此时再启动一个启动器不会发现前一个实例，会第二个服务写同一个数据库。触发需要同时满足「8765 被外人占」与「重复启动」，暂不为它引入锁文件或全端口扫描。
