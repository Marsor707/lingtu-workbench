# ADR 0007：生图结果按提交批次归入任务文件夹

## 状态

已采用

## 背景

生图结果原先全部平铺在工作区的 `jobs` 目录，批量改图或重复生成后目录内会混入大量文件，人工按"这一次任务"归档和查找都很困难。一次「开始任务」提交可能展开为多个任务（改图一次选择多张源图时，每张源图是一个任务），因此需要一个比任务更大的归集单位。

## 决策

- 引入「提交批次」：一次「开始任务」操作生成一个批次标识，本批次的所有任务共享它；批次标识保存在任务请求快照中，不单独建表。
- 批次标识由前端在提交时生成并透传，后端用文件系统安全的字符集强校验，防止路径穿越。
- 结果写入 `jobs/<批次标识>/`；缺少批次归属的历史任务写入 `jobs/<任务 ID>/`。
- 任务文件夹在写入首张结果前按需创建，失败任务不留空文件夹，被手工删除的文件夹在重试写入时自动重建。
- 批次文件夹内的文件命名沿用原规则（任务 ID 加序号，或 LLM 命名加同名序号）。
- 历史平铺结果不迁移，接口继续按任务快照中记录的路径读取。
- 本次不改动前端展示：结果仍通过任务结果索引接口读取，目录布局属于本地实现细节。

## 结果

同一批次的产出集中在一个文件夹，重试结果回到原批次文件夹，便于人工归档与核对。批次不是独立生命周期实体，删除、统计和状态仍以任务为准；历史任务保持可读，不承担一次性搬迁数据的风险。
