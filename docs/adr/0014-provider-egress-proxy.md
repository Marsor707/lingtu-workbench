# 0014 出网代理由应用配置决定

## 背景

用户反馈：同一个 Provider，生图耗时超过约 1 分钟时大概率失败，但 Provider 后台能看到请求已受理并已扣费。

日志给出了无重叠的分界：成功请求全部落在 26.9~58.7 秒，失败请求集中在 60.5~63.3 秒，错误码是 `provider_network_error`，`errorDetail` 显示 `TypeError: fetch failed <- SocketError: other side closed (UND_ERR_SOCKET)`。即**远端主动断开连接**，不是应用自身的 3 分钟超时（那会记为 `provider_timeout`）。

原因是 Proxy 链路里的长连接空闲超时：生图请求体发出后要静默等待数十秒，这段时间链路上没有任何字节流动，中间设备按空闲超时回收了连接，而 Provider 侧仍在继续生成并计费。同一个 Provider 在开发机上拿到过 133 秒的成功响应，说明分界来自用户侧链路而非 Provider 本身。

在此之前，出网代理是隐式的：Rust 读取 Windows 注册表（或 macOS `scutil --proxy`）里的系统代理，转换成 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` 环境变量注入 sidecar，并打开 `NODE_USE_ENV_PROXY`。用户既看不到自己在走代理，也无法只让某一个 Provider 直连。

## 决策

**出网代理由应用配置决定，不再读取进程环境变量。**

- `lib.rs` 只把检测到的系统代理作为 `LINGTU_SYSTEM_PROXY` 传给 sidecar，不再注入 `HTTP_PROXY` 等变量，也不再设置 `NODE_USE_ENV_PROXY`。
- 工作区设置新增全局「网络代理」，三态分段控件：`跟随系统`（存空串，取启动时检测到的系统代理）/ `直连`（存 `direct`）/ `自定义`（存代理地址）。空串的语义是「跟随」而不是「直连」，这样改 Clash 端口后重启即可生效，不需要回到界面重填。
- 每个供应商（生图与 LLM）新增三态代理：`跟随全局设置`（默认，存空串）/ `直连`（存 `direct`）/ `自定义`（存代理地址）。
- 实际出口 = 供应商级配置叠加全局设置，每次任务执行时重新解析，改完设置重试即可生效。
- 全局与供应商两级共用同一套取值编码（空串/`direct`/地址），前端也用同一个模式解析函数，避免两处语义漂移。
- 所有出站请求（生图、结果图片下载、LLM、检查更新、下载安装包）统一走 `server/network.ts` 的 `networkInit()`，直连时也显式传入一个 `Agent`，确保环境里残留的代理变量无法改变出口。

## 后果

- 用户第一次能看见并修改自己的出口。遇到上述 60 秒问题，把该供应商改成「直连」即可，不必关掉整个代理软件。
- 升级不改变既有行为：桌面版启动时会把检测到的系统代理填成全局默认值，等价于原来的隐式行为。
- **代理软件开启 TUN 模式时这个决策不生效**：TUN 在内核路由层接管流量，应用层走不走代理端口都会进代理软件。设置页里必须显式说明这一点，否则用户会以为「已经设了直连却仍然失败」。
- 引入了 `undici` 依赖以取得 `ProxyAgent`：Node 内置 fetch 只接受与其内部版本一致的 Dispatcher（实测 undici v8 报 `invalid onRequestStart method`，v7 正常），因此锁定 `undici@^7`，并在 `provider.test.mjs` 里用本地 CONNECT 代理做回归测试——Node 大版本升级导致不兼容时该测试会先失败。
- 代理地址不接受账号密码：接口会把供应商配置回传给前端，凭据无法像 API Key 那样整体剔除。需要认证代理时再单独设计脱敏回显。
- 不再依赖 `NO_PROXY`，因此 Rust 侧的系统代理检测不再解析绕过列表。
