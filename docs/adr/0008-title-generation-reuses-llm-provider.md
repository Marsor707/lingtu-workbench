# ADR 0008：商品标题生成复用 LLM 供应商并共用统计

## 状态

已采用

## 背景

商品标题生成需要带视觉输入的 LLM：把商品图连同七类标题模板提示词一起发给模型，取回固定七个类别的标题。

项目里已有一套 LLM 供应商注册表，但它是在 ADR 0004 中为「图片命名」建的，连接档案、启用状态和成功/失败统计都按图片命名定义（见 `CONTEXT.md` 的「LLM 供应商」）。如果为标题生成再建一套连接档案，就会同时存在两个「当前模型」概念，密钥也要再配一遍。

真正需要权衡的是：两种用途要不要各自独立的启用状态与统计。

## 决策

- **复用同一个 LLM 供应商注册表**，沿用「系统任意时刻最多一个启用 LLM 供应商」的语义。标题生成只读使用当前启用项，页面不提供第二个选择维度，也不参与工作区里的「图片命名」开关。
- **共用成功/失败统计**：标题生成的一次调用按最终结果累加到同一个 LLM 供应商计数上，与图片命名合并；供应商统计从此表示「LLM 调用」而非仅图片命名。
- **不参与运行锁**：标题生成请求不计入 `runningCount`，因此不会阻止切换或删除 LLM 供应商。请求很短，且不产生任务快照；切换发生在请求中途时，本次仍使用请求开始时的密钥。
- **由后端代理调用**：新增 `POST /api/title-generation`，密钥不出后端（沿用 ADR 0001、ADR 0004 的约束）。

## 结果

只需配置一次 LLM 连接即可同时用于图片命名和商品标题生成，`CONTEXT.md` 中「LLM 供应商」的定义随之更新为两种用途共用。

代价是统计口径变宽：单看成功/失败计数无法再区分是图片命名还是标题生成产生的。这是有意的取舍——页面不展示按用途拆分的数字，无需为此维护第二套计数。

标题提示词不再写死在代码里，而是作为用途为「商品标题」的提示词资产存进提示词库，用户可编辑、可新增多个版本；输出版本契约由后端校验保证，模型返回的类别缺失或多余时该图判失败。
